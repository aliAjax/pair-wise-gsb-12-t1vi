# 山路冷链 · 派车交接台

单换车、司机休息常断在半路的冷链派车台。沿用既有技术栈（Vue3 + Vite + TypeScript + Pinia + Element Plus），无新增依赖，数据存浏览器 localStorage，重开页面可续看。

## 分层（资料 / 判断 / 留档 / 界面分开维护）

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 资料 | `src/types.ts` | 订单（线路/送达窗口/货温/重量）、车辆（核载/温区/保养里程点+日期）、司机（班次/连续驾驶时长）、运次 |
| 判断 | `src/rules/dispatch.ts`、`src/utils/time.ts` | 纯函数：撞班、温区、核载、保养里程/时点、班次覆盖、连续驾驶休息，全部不通过即返回缺口列表 |
| 留档 | `src/stores/dispatch.ts` | Pinia：派车/拦截/交回/接续/送达/休息/资料变更日志，localStorage 持久化 |
| 界面 | `src/App.vue`、`src/components/*.vue` | 派车交接台、资料维护、留档查询三个页签 |

## 业务规则

- **撞班**：同一车辆或同一司机的在途运次时间区间重叠即拦截（交回后立即释放，不再参与撞班）。
- **温区/核载**：车辆温区须覆盖货温，货重不得超过核载。
- **保养**：跑完剩余线路不得越过下次保养里程点；预计送达不得晚于保养到期日。
- **班次**：驾驶区间（按山路均速 30km/h 估算）必须落在班次内，下班时间早于上班按次日处理。
- **连续驾驶**：满 4 小时必须先休 20 分钟（硬缺口）；未满 4 小时但本程会超时，提示途中安排休息（不拦截）。
- **派车失败**：订单留在待派区，缺口（人话说明）写回订单并记入日志。
- **发车锁定**：派车成功后车+司机组合锁定。
- **途中改派两步**：① 交回剩余线路，登记原因与已跑里程/分钟，原车/原司机占用**立刻释放**；② 待接续运次按剩余线路重新校验新车+新司机，确认后继续承运。交回记录含原车、新车、已跑里程、原因。
- 实际行驶里程落入车辆表显与司机连续驾驶时长，影响后续派车判断。

## 启动

```bash
npm install
npm run dev        # 开发
npm run build      # tsc 严格类型检查 + 构建
```

纯逻辑冒烟测试（不依赖浏览器，Pinia store 在 Node 中执行）：

```bash
node_modules/.bin/esbuild scripts/smoke.ts --bundle --platform=node --format=esm --outfile=/tmp/smoke.mjs
node /tmp/smoke.mjs
```

覆盖：派车成功、撞班/载重/温区/保养/休息拦截、缺口写回待派区、交回立即释放、接续再校验、送达、日志与持久化。

页面右上角"重置演示数据"可清空 localStorage 并恢复随当前日期生成的演示数据。
